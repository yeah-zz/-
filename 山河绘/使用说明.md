更新日期：2026-09-30。当前电脑的项目路径为 `G:\山河绘`；换盘符时改终端进入的目录即可。所有新图统一使用“按参考图绘画”，不再按山水、花卉分模式。历史单幅梅花描边任务、黑/红命令及借用绿色工位说明见 [梅花描边运行说明](梅花描边运行说明.md)。历史标定值不作为当前操作依据。

## 当前日常流程（2026-10-01）

双击启动菜单，选1读取绘画 JSON；程序先画黑线，每次上色或换色前停住等你洗笔并输入颜色。绘画中按 P 完成当前笔并停到纸外；C 继续，Q 保存退出，下次同一个 JSON 从下一笔续画。详见 [JSON绘画与暂停续画](docs/JSON绘画与暂停续画.md)。

新生成 `_完整绘画.json` 是真正的单文件画稿。下文旧命令仍保留，但其独立执行日志不等于新菜单的会话进度；不要在同一张纸上混用入口。

## 2. 日常运行：推荐直接使用 .venv

在项目目录打开 PowerShell。当前电脑进入目录：

```powershell
cd "G:\山河绘"
```

先检查环境是否能用：

```powershell
.\.venv\Scripts\python.exe -c "import sys, numpy, cv2; print(sys.executable); print('环境正常')"
```

`.venv` 是主环境。启动菜单会先检测解释器；若旧环境失效则回退到 `uv run --locked` 重建并启动，首次可能需要联网。`.展示运行环境` 是之前保留的兼容环境，不是日常首选；名字含 broken 的目录和 archive 中的环境是备份。`uv run --locked python ...` 通常也使用项目 `.venv`，但会先检查依赖；直接调用 `.venv` 则不自动同步依赖。

## 3. 已保存的画：先检查，再绘制

以下以整理时通过当前离线检查的“近石远山·蓝绿新画布”举例。通过离线检查不代表实物已验收；现场或配置变化后应重新检查。

本次25份任务中，24份因标定／设置与当前配置不一致未通过，包括以前的松树专项任务；详见画稿清单。不要通过覆盖当前现场标定来强行运行旧画。

### 3.1 离线检查两份文件

```powershell
.\.venv\Scripts\python.exe run_mountain_balanced.py --job "输出\近石远山_蓝绿新画布_20260928\近石远山_蓝绿新画布_黑线任务.json" --check
.\.venv\Scripts\python.exe run_color_from_job.py --job "输出\近石远山_蓝绿新画布_20260928\近石远山_蓝绿新画布_计划.json" --check
```

`--check` 不连接机械臂。它检查任务结构、标定一致性和计划轨迹等，不能判断实物纸张是否放好或途中是否有障碍。

### 3.2 画黑线，然后等待上色

```powershell
.\.venv\Scripts\python.exe run_mountain_balanced.py --job "输出\近石远山_蓝绿新画布_20260928\近石远山_蓝绿新画布_黑线任务.json"
```

运行后显示任务，输入 `RUN` 才进入实机执行。黑线完成后抬笔，自动读取同目录同名前缀的 `_计划.json`，停住等待换色。

等墨干、洗净擦笔或换笔并核对笔尖高度后，按屏幕列出的剩余颜色输入，例如 `蓝` 或 `绿`；含黄色的其他画稿才选择 `黄`。每色完成再次停住，顺序由你选择。回车或 `0` 结束。程序不会自动洗笔或换颜料。

若配套计划名称不同，用 `--colors-job "完整计划路径"` 指定。不要把不同图片的黑线和上色计划混用。完整入口总是从黑线第一笔开始，不能当作续画入口。

### 3.3 只上色，不重画黑线

```powershell
.\.venv\Scripts\python.exe run_color_from_job.py --job "输出\近石远山_蓝绿新画布_20260928\近石远山_蓝绿新画布_计划.json"
```

使用对应的已勾线纸张，保持位置不变；只选择尚未画过的颜色。该入口会读取配套黑线任务核对标定，但不执行黑线。配套名称不同时用 `--ink-job` 指定。

同一次选色会话会防止重复画已完成颜色；退出重开后不会自动记住哪些颜色已画完，不能随意重复选择。

## 4. 从新图片生成预览

1. 双击 `启动菜单.bat`，选 `2` 从图片生成绘画 JSON 和预览。
2. 输入原始图片路径，或把图片拖入终端。不要把路径预览当作原图再次提线。
3. 程序在 `输出` 生成预览、提取线稿、黑线任务、计划和单文件 `_完整绘画.json`。
4. 只看预览，按回车返回；输入 `PAINT` 会进入绘画流程，仍需按现场提示确认。

山水、梅花及其他题材共用原图连续提线、黑墨勾线和按色区面积铺色，不再给花卉强制每区最多两笔。旧命令行的稀疏铺色参数 `--strokes-per-region` 也可设任意正整数。

这条通用流程不自动应用针对某幅画手工制作的“疏淡上色”“松树专项”等修改。要画这些版本，应直接读取它们已经保存的 JSON。

预览是路径与估计笔宽、颜色的示意，不是实际晕染结果。多数旧预览按每笔平均线宽显示；松树专项预览按逐点下压估算线宽。提取线稿也不是最终机械臂轨迹。

## 5. JSON、纸面高度与粗细

| 文件／字段 | 用途 |
|---|---|
| `_黑线任务.json` | 黑线笔触、逐点下压、轨迹及生成时的标定快照 |
| `_计划.json` | 黑线预览信息、颜色路径、上色运动参数和配套图像信息 |
| `config.py` | 当前纸面、画布四角、坐标系、姿态、可达范围、下压范围等 |
| `pigment_measurements.json` | 各色杯位、杯沿、液面、蘸取深度、停留和沥液时间等 |
| `ink_control.py` | 新任务默认补墨策略；旧任务还带有自身策略快照 |

整理时配置为 `PAPER_Z=-12.6252`，下压范围配置为0.06～0.30 mm；这些不是可以照抄到任意现场的通用标定值。起收笔的逐点下压可以小于配置下限。

本项目当前方向：`实际行笔Z = PAPER_Z + press`。例如 press=0.20 mm 时，Z=-12.4252。`PAPER_Z` 表示刚触纸的基准，`press` 表示从基准继续下压的量。它不是毛笔压力传感器的读数。

改变笔长、触纸高度、画布位置、姿态或坐标系后，需要重新测量并更新任务，再离线检查。只修改 config 不会改写旧 JSON；不要为了通过检查而只改 JSON 的标定字段、忽略实际轨迹。

杯子移动或液面变化也应更新杯位配置。当前黑线加载器允许部分杯位参数作为运行时输入重新校验；不能据此认为所有标定都可随意变化。

## 6. 启动位置、进度与速度

输入 RUN 后，黑线执行器读取机械臂状态和位姿，要求已使能、空闲、无报警；检查姿态偏差、起点深度、起点及抬笔终点可达范围。当前不要求在固定停车点附近启动。通过后先原地抬笔，再蘸墨和画第一笔；这不是障碍物检测。

黑线和每种颜色都会显示完成笔数、百分比及蘸取次数，并保存执行记录。黑线按耗墨估计、时间等补墨，不按固定1～2笔补墨。上色按各杯 `strokes_per_load` 限制，还可能因累计长度将超过50 mm或蘸色后超过60秒提前补蘸；实际值看当前杯配置。

新生成黑线任务默认 `rest_every=0`，即不再每20笔固定休息20秒。旧 JSON 自带策略，可能仍有固定休息；见画稿清单，不能只看当前代码默认值。

笔间抬高由任务的 `lift_mm` 决定；松树专项黑线为4 mm，上色未指定时默认5 mm。蘸取、返回和结束仍使用高位转移。不要为了加速直接取消杯边高位转移。

## 7. 卡住、续画、换新纸

### 放弃旧画，换新纸

先在控制器停止运动并取消旧队列，确认笔离纸，结束旧绘画程序，再双击 `放弃旧任务.bat`。它显示待放弃的黑线和上色记录数量，输入 `NEW` 才处理。

该入口保留日志与未完成动作证据，标记旧记录已放弃，并归档上色锁；不删除画稿和成功记录，不停止或移动机械臂，不自动开始下一幅。范围是 `输出`、展示选画目录内的黑线运行日志和共用 `robot_runs` 内的未解决上色记录。

黑线历史记录本来不会拦截新画；上色的未解决记录或锁可能拦截其他画稿。黑线程序没有相同的运行锁检测，必须先关闭旧黑线进程。不要直接删除日志或锁来跳过问题。

### 原纸接着画

不要使用放弃入口，也不要从完整任务第一笔重跑。要根据最新日志和纸面最后一笔确定续画起点；最后一筆可能只画了一部分。

名字含“从第…笔续画”“剩余”的 JSON 是特定纸张和中断状态下生成的任务，不能当新图入口。旧入口仅有底层续画工具。新菜单1支持经过正常 P/Q 暂停的按笔续画，详见顶部的新流程。

Ctrl+C 只中断程序，不保证控制器立即停止或旧队列清空。

### 日志在哪里

- 黑线：任务 JSON 旁边的 `<任务名>_runs`，包含 `_execution_log.json` 和 `_actual.json`。
- 上色：项目 `robot_runs/color_experiment_*.json`。
- `completed_strokes`／`contacts` 反映执行记录，`success=true` 表示该次执行完成，不是美术质量验收。

## 8. U盘换电脑、换盘符和依赖安装

详细逐步操作见[U盘换电脑说明](docs/U盘换电脑说明.md)，其中解释了为什么换电脑后环境可能反复失效。

当前仍采用项目内 `.venv`，没有实现“每台电脑本地缓存环境”的自动切换。

新电脑安装 uv 后，将 U 盘上旧 `.venv` 改名备份，在项目目录运行：

```powershell
uv sync --locked --python 3.12
```

通常需要联网准备 Python 和依赖。项目主要依赖 NumPy、OpenCV；不需要逐个 pip 安装。`.venv` 依赖解释器路径和系统，不能认为 U 盘上的环境跨电脑通用；换回原电脑也可能需要处理环境。

频繁换电脑时，建议每台电脑各有本地环境或本地项目副本，同步代码、画稿和配置时不覆盖环境。未来可改成U盘代码＋本机环境，但目前入口尚未采用此方案。

大部分启动脚本按自身位置定位，VS Code使用`${workspaceFolder}`。部分JSON仍含绝对参考图路径和历史来源；移动后需要核对配套引用，不能批量改写历史日志中的路径／哈希。重新打开新目录并新建终端，避免使用旧激活环境。

机械臂网络连接、IP和现场标定需要在新电脑单独核对，安装依赖不会自动配置这些。

## 9. 常见提示

| 提示／现象 | 处理方法 |
|---|---|
| `No Python at ...` | 环境引用的Python已不存在；备份失效环境后用uv重建 |
| `Calibration/settings changed; regenerate and review` | 当前标定与任务不一致，核对实测值并更新任务 |
| 姿态不符／未使能／报警 | 根据实际控制器状态处理；程序不会自动恢复所有状态 |
| 上一条中断记录还没了结 | 原纸续画先核查日志；换新纸按第7节放弃旧任务 |
| 未找到同名配套上色计划 | 黑线入口会结束；核对文件前缀或使用`--colors-job` |
| 找不到图片或配套黑线 | 检查JSON文件名和路径，特别是移动U盘或改项目名之后 |
| 遍历日志出现“有更多数据可用”等I/O错误 | 属于目录读取问题，不能当作没有日志或没有中断；保留数据并检查U盘目录，勿据此手动删锁 |
