# 流程与限制说明

## 山水和梅花有模式上的区别吗？

机械臂不需要识别题材模式。区别在于图像里的线条、色区和所需笔触：山石可能需要长线和大面积铺色，花瓣可能需要短线、轮廓和点染。一张图也可以同时包含山水和梅花。

旧菜单确实接了两套算法：

| 项目 | 原“画山水” | 原“画花” |
|---|---|---|
| 提线 | original_d_adapter 连续提线 | reference_lines 提取轮廓后交 legacy_mountain_adapter |
| 铺色 | landscape_color 按面积铺色，附加绿色短点 | sparse_color，每个色区最多两笔 |
| 执行 | 同一套黑线执行器、补墨、选色、杯位和上色执行器 | 与山水共用 |

这些是历史实现差异，不是山水和梅花必须遵守的绘画规则。

## 现在统一为什么

菜单只保留“按参考图绘画”。所有新图共用原山水入口的连续提线和按面积铺色算法，绿色短点按图片证据生成。旧调用的 subject 参数只为兼容保留，不再决定算法；新计划标记 subject=reference。

取消花卉每区固定最多两笔的分支。单独使用稀疏铺色工具时，笔数上限可配置为任意正整数，默认仍为2。通用面积铺色仍保留原有最多1800笔的计算规模上限、微小色区过滤等参数；本次没有声称消除所有算法阈值。

这次是统一已有流程，不是新增花瓣识别或自动选择最佳笔法。旧梅花专项的黑红描边、点染和借杯安排不会自动迁移到新图，需要时继续读取该专项画稿。

## 保留的检查及原因

- 纸面映射、可达范围、边缘余量：避免轨迹出纸或超出运动范围。
- 下压、姿态、抬笔和杯沿检查：对应笔与机械臂的实际位置关系。
- 标定快照核对：防止旧画稿沿用已经变动的坐标与高度。
- 执行前确认、换色停顿及未完成任务记录：避免预览直接运动、未换笔就上色和重复执行。
- 暂不接受自定义 IMAGE_CORNERS：当前黑线执行器使用整图映射，删除报错并不能补齐映射支持。

## 目录整理原则

根目录保留 Python 模块原位置，防止破坏导入和旧画稿引用；README 作为唯一导航首页。标定、原图、输出和执行日志不清理。历史专项说明保留供旧任务使用，不再作为新图入口。修改前文件备份在 archive/统一绘画入口_时间戳。
