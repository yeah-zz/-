**入口已改用好提取器**(改动在 `unified_painting.py` 的 `build_plan()`)。实测(飞瀑松崖):

| | 改动前 | 改动后 |
|---|---|---|
| base_strokes | 612 条 | **5052 条** |
| design_origin | `D-original-600px` | **`full-resolution-source-width`** |
| 提取线稿 png | 241 KB | **588 KB** |

改法:笔触改用 `width_strokes`(好提取器),**`stats` 仍沿用旧提取器** ——
下游 `quality_stats` / `ink_execution` 依赖旧 stats 的字段,两个都跑最稳妥
(多花几秒,不会因字段缺失而崩)。

### 底层 API

```python
# scripts/preview_contrast_landscape.py
width_strokes(work, scale, pad=None, source_image=None)
   algorithm = 'full-resolution-width-and-in-mask-rails'
   笔触字段: name='原图墨线宽度分层'
            design_origin='full-resolution-source-width'
            role  = 'source_center' | 'source_broad_rail'
            layer = 0 | 1 | 2
```

| 决定性优势 | 说明 |
|---|---|
| **全分辨率** | 不降采样。旧 D 版会先把长边压到 600px,细节在那一步就丢了 |
| **按原图墨线宽度分层** | 用原图墨迹的距离变换算出每条线的真实粗细 → 决定 role / layer / 笔压 |

> 注:`unified_painting.py` 第 22 行的 `outline_image()` 里还写着 `reference_lines.extract`,
> 但 **`build_plan` 从不调用它,是死代码**。以后清理可以直接删。
> 另有独立入口 `scripts/提取线稿.py`(只出笔触 JSON + 预览,不组装上机任务)。

## 其余提线器(归档,不要用于新画)

## 新图应该怎么走(以飞瀑松崖为例)

```
参考图\飞瀑松崖_20260930.png
   ↓  scripts\提取线稿.py            全分辨率 + 宽度分层
      → 5052 条 (source_center 5052, 0 条宽笔道)
   ↓  scripts\simplify_filled_landscape.py   简化
      5052 → 预计 1200~1600 条(层峦松水是 1763→553,约 3.2 倍压缩)
      ⚠ 该脚本现在读死 层峦松水_快速起落_黑线任务.json,要改成读新图的
   ↓  scripts\build_filled_landscape.py        上色 + 色阶
   ↓  出"黑线+上色"预览 → 归档 → 上机
```

**为什么必须先简化**:5052 笔上机时间会长到不现实(层峦松水 553 笔的黑线阶段已是约 30 分钟)。
简化阈值(2.4mm / 4.0mm)可能要按这张图调 —— **它的墨线密度是层峦松水的约 3 倍**。
