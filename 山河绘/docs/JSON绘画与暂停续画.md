# JSON 绘画、换色、暂停与续画

更新：2026-10-01。

## 一份 JSON 就能画吗

可以，推荐 `_完整绘画.json`，格式 `arm-painting-bundle-v1`。内部包含 workflow（黑线和上色计划）与 ink_job（黑线笔触、轨迹、标定快照），不依赖同目录的配套 JSON，也不需要重新读取原图。

这不代表任意 JSON 都能画。必须包含本项目支持的笔触数据，并通过当前现场标定和轨迹检查。新图从菜单2生成完整绘画包；旧 `_计划.json` 可以直接从菜单1读取，但仍需要同名 `_黑线任务.json`。也可提供黑线任务，程序会寻找同名计划；没有配套计划就只画黑线。

把旧计划打包成单文件（离线，不连接机械臂）：

```powershell
.\.venv\Scripts\python.exe run_json_painting.py --job "输出\某画_计划.json" --pack "输出\某画_完整绘画.json"
```

检查任一支持的 JSON（离线）：

```powershell
.\.venv\Scripts\python.exe run_json_painting.py --job "输出\某画_完整绘画.json" --check
```

## 绘画和洗笔

1. 菜单1拖入 JSON，核对画稿、纸和笔，输入 RUN。
2. 从第一笔黑线开始；如果这份 JSON 有已保存进度，就从下一笔继续。
3. 黑线完成后抬笔停到纸外，等你等墨干、洗净擦笔或换笔。
4. 输入待画颜色，例如 红、黄、蓝、淡蓝、绿，也支持英文。程序只画选择的这一种。
5. 每色完成后再次停到纸外。你不输入下一种颜色，它就一直等待，洗笔没有倒计时。
6. 选色时回车保存退出，下次打开同一 JSON 不会重画已完成黑线或颜色。

绘画期间只更新一条进度条，显示当前颜色（或黑线）的完成笔数和百分比。底层动作明细写在 robot_runs/painting_session_*.log；暂停、换色和错误信息仍会显示。

## 暂停、调整、继续

- 在绘画终端按 P，无需回车；程序完成当前笔，再抬笔停到纸外。必须等“已抬笔停在纸外”出现后再操作。
- C：核对机械臂停靠位置后继续内存中的当前计划，重新蘸墨/蘸色，不重复已完成笔触。
- Q：保存并退出当前绘画；重新打开同一路径的 JSON，从下一笔继续。上色续画仍需再次输入该颜色，留出洗笔时间。
- 想调整后续画法：先 P、Q，再改同一文件中未画笔触的 points、press、speed 等实际规划数据，重新打开校验。只改预览模块不会自动重建黑线执行笔触；黑线执行数据位于 ink_job.meta.ink_execution.base_strokes。
- 不支持在一笔中间随意改路径后接着半笔画；也不能撤销已经落在纸上的笔触。
- 已画前缀不能删除、修改、重新排序；画布、坐标系、纸面高度及全局运动档案改变时拒绝沿用进度。重新装笔导致笔尖高度变化时，应先重新标定，不可按原标定继续。
- C 不会热加载文件改动；要让修改生效，请 Q 退出后重新打开。修改 config.py 后应退出整个程序再启动。

进度保存在 robot_runs，以输入 JSON 的完整路径识别同一幅画。续画时保持文件名、路径和进度目录不变。复制/改名被当作另一幅画，不能用来继续原纸。已全部完成时再次打开会提示完成；换新纸重画可将 JSON 复制为新文件名。

P 是按笔暂停，不是即时急停。Ctrl+C、断电、控制器急停或未知运动失败可能留下半笔；这些状态不会自动猜测续画位置。异常退出还可能保留会话锁。应先确认控制器停止、核查日志与纸面；决定放弃原纸时才使用放弃入口。

## 放弃旧任务到底做什么

菜单3与“放弃旧任务.bat”同时处理：

- 输出、展示选画与 robot_runs 内的未完成黑线执行记录。
- 共用上色执行器的未解决动作记录。
- 新 JSON 入口的整幅画进度，包括已完成黑线后等待上色、部分颜色完成、按 P/Q 保存的任务。

它标记这些记录已放弃，并归档锁文件；原始画稿、实际运动记录和成功记录保留。下次打开被放弃的 JSON 会按新纸从头画。

它不向机械臂发送停止命令。请先用控制器停止并清空旧队列、抬笔、结束绘画程序，再输入 NEW。新 JSON 会话仍在运行时，放弃入口拒绝修改记录。只是想暂停或继续同一张纸，使用 P/Q，不要点放弃。

旧脚本仍可运行，但不自动继承新会话的跨次进度。日常执行与续画统一使用菜单1，避免混用入口造成重复绘画。
