# U盘在不同电脑上的环境说明

更新：2026-09-28。当前入口使用U盘项目中的`.venv`。**尚未启用“每台电脑本地保存环境”的自动切换方案。**

## 为什么总是需要处理环境

U盘里的代码和画稿可以随盘复制，但`.venv`不是通用的便携Python。它会引用创建它的电脑上的Python路径，还依赖操作系统和架构。

例如本次检查发现`.venv/pyvenv.cfg`指向`D:\Anaconda3`，而当前电脑没有这个解释器，所以提示`No Python at ...`。这不是画稿坏了，也不是每画一次都必须重装库。

在A电脑建立的U盘环境，带到B电脑可能失效；在B电脑重建同一个`.venv`之后，插回A电脑也可能不兼容。因此，当前“同一U盘同一个.venv”的结构确实可能反复需要重建。

## 第一次在新电脑运行

1. 安装uv。可在Windows终端使用以下安装命令；若没有winget，可按uv官方安装说明操作。

```powershell
winget install --id astral-sh.uv -e
```

安装后重新打开终端，用`uv --version`检查。官方安装说明：https://docs.astral.sh/uv/getting-started/installation/

2. 在资源管理器打开U盘的“山河绘”目录，再在该目录打开PowerShell。这样不需要记住当前是G盘还是E盘。
3. 若已存在旧`.venv`，在关闭所有使用该环境的绘画程序后，将其改名备份，例如`.venv_旧电脑_日期`。不要覆盖同名备份。
4. 在项目目录运行：

```powershell
uv sync --locked --python 3.12
```

uv会准备匹配的Python（需要时下载）、创建`.venv`并按锁文件安装依赖；主要是NumPy和OpenCV。首次通常需要联网，不必逐个安装这些库。它不会替你设置机械臂网络或标定。

5. 检查环境：

```powershell
.\.venv\Scripts\python.exe -c "import sys, numpy, cv2; print(sys.executable); print('环境正常')"
```

成功后即可使用现有bat或主使用说明中的命令。Python版本一致还不够：网络、IP、用户／工具坐标系、笔和纸面标定也必须核对。

## 回到以前用过的电脑

先执行上面的环境检查。能正常导入就继续使用，无需再次安装；如果解释器路径失效，则备份当前`.venv`后重建。不要修改pyvenv.cfg的home来强行拼接不同版本的Python与已有二进制库。

同一电脑同一有效环境，日常不必反复重建。依赖更新时可运行`uv sync --locked`同步；不用每次画图前删除环境。

## 如果想长期避免反复重建

每台电脑各存一份本地项目／本地环境，U盘负责携带代码、画稿、配置与记录；同步时不要覆盖本地`.venv`。另一种做法是改造启动脚本，让U盘代码自动选择本机缓存环境，但**本项目当前没有启用这一方案**。

本轮按用户要求，以说明为主；现有启动入口保持使用项目`.venv`，未启用新的自动环境切换入口。

## 两种运行写法

- `.\.venv\Scripts\python.exe ...`：直接使用已经配好的环境，适合日常绘画。
- `uv run --locked python ...`：先检查／同步环境依赖，再执行；不是更快的绘画算法，也不保证自动修复损坏的旧环境。

`.展示运行环境`是历史兼容环境，同样不保证跨电脑通用；不要把它当成另一种便携方案。
